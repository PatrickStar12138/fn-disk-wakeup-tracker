# fnOS 真机验收清单

当前状态：**全部待真机验证**。本地测试不会读取或改变开发机硬盘电源状态。

记录设备型号、fnOS 完整版本、内核、控制器/USB 桥接芯片、安装卷介质类型、测试人和时间。每项保留命令输出或截图，但不得包含 Token、Cookie、密码和完整序列号。

## 安装与生命周期

1. 在 x86 fnOS 手动安装 `fn-disk-wakeup-tracker-x86-0.1.0.fpk`。
2. 在 ARM fnOS 手动安装 `fn-disk-wakeup-tracker-arm-0.1.0.fpk`。
3. 启动应用，确认 Server 和 Collector 各只有一个进程。
4. 停止应用，确认进程和两个 Socket 都消失，SQLite 正常关闭。
5. 重启应用，确认不产生虚假的“刚刚唤醒”事件。
6. 从 fnOS 桌面入口打开 `/app/fn-disk-wakeup-tracker`。
7. 管理员访问全部页面和 API 成功。
8. 普通用户看不到入口；直接访问返回 403。
9. 检查 `${TRIM_APPDEST}/app.sock`、`${TRIM_PKGVAR}/run/collector.sock` 所有者和权限。
10. 使用 `ss -lntup` 确认应用没有外部 TCP/UDP 监听。

## 设备与事件

11. 验证 SATA/SAS/USB 物理盘扫描结果，序列号只显示脱敏值。
12. 对机械盘分别验证 active、idle、standby、unknown，特别确认 unknown 不显示为待机。
13. 验证 SSD/NVMe 显示“不支持/不适用”，不产生虚假休眠状态。
14. 在已确认硬盘待机后主动读取一个普通文件，确认只记录一次 `disk_wakeup`。
15. 核对疑似来源含 PID、读写增量、时间窗口、可执行路径/应用/容器和可信度。
16. 确认 Server/Collector 自身 I/O 标记为应用自身并从默认来源排行排除。
17. 连续运行至少 24 小时，检查重复事件、内存、CPU 和 Collector 健康状态。
18. 记录 SQLite 初始、1 小时、24 小时大小，确认不按采样频率持续增长。
19. 制造受控错误验证日志轮换、大小上限和保留数量。
20. 从 0.1.0 升级测试包，确认配置、数据库和历史事件保留且迁移失败可恢复备份。
21. 卸载选择“保留”，记录卸载各生命周期阶段 `etc/var/home` 的存在状态。
22. 重新安装并确认旧配置和历史恢复；如果系统清理目录，记录失败并阻止发布。
23. 卸载选择“删除”，确认只删除本应用配置、数据库、事件、日志、临时和诊断文件。
24. 重新安装确认旧数据已清除，其他应用和用户文件不受影响。
25. 重启 fnOS，确认应用按系统策略恢复且不重复启动进程。
26. 强制终止 Collector，确认两分钟后记录一次离线事件，恢复后记录一次恢复事件。
27. 多块机械盘同时变化时确认状态和事件不串盘。
28. USB 盘拔出记录离线/未知，重新接入记录重新接入而不是普通唤醒。

## 最关键：30 分钟以上空闲对照

同一硬件、相同系统负载和相同硬盘待机设置下执行两组至少 30 分钟测试：

### A. 应用未运行

- 记录硬盘进入待机的时间和状态检测依据。
- 记录系统基线 I/O 和其他常驻进程。

### B. 应用运行

- 先保持 `enableHdparmProbe=false` 完成一轮。
- 如控制器厂商资料和实际对照表明 `hdparm -C` 不会唤醒，再显式开启并完成第二轮。
- 每 5 分钟记录 Server/Collector 的 `/proc/<pid>/io`。
- 记录 SQLite WAL/数据库写入次数与时间。
- 记录 Server/Collector 日志写入次数与时间。
- 记录状态检测命令调用频率和返回值。
- 确认机械盘仍能在预期时间进入待机，并保持待机。
